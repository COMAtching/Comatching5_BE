# 다른 PC에서 시작하기

이 ZIP은 직접 만든 **KB 거래내역 → JSON 검증용 Chrome 확장 프로그램**입니다. Mac에는 은행 보안 프로그램을 설치하지 않았으며, 실제 은행 접속 검증은 다른 PC에서 진행하는 것으로 남겨 두었습니다.

## 설치와 추출

1. ZIP을 다른 PC로 옮겨 압축을 풉니다. **Node.js나 npm 설치는 필요 없습니다.**
2. Chrome 주소창에 `chrome://extensions` 입력 → 개발자 모드 켜기 → **압축해제된 확장 프로그램을 로드합니다** → 압축을 푼 폴더 안의 **`extension` 폴더**를 선택합니다.
3. [KB 개인뱅킹 거래내역 조회](https://obank.kbstar.com/quics?page=C102264)에 로그인해 보유한 KB 계좌를 선택합니다. 기억나는 입금이 있는 날짜를 조회해 해당 거래가 보이는 탭을 열어 둡니다. 이미 빠른조회에 등록한 계좌라면 [KB 빠른조회](https://obank1.kbstar.com/quics?QSL=F&cc=b028364%3Ab028702&page=C025255) 결과 화면에서도 같은 절차를 시험할 수 있습니다.
4. 은행 탭에서 Chrome 퍼즐 아이콘 → **코매칭 입금 장부**를 엽니다. 은행과 별칭을 확인한 뒤 **거래내역 읽기**를 누릅니다. 표나 열이 여러 후보면 **표와 열 설정**이 열립니다. 원본과 비교하고 **선택한 열 적용**을 누르세요.
5. **전체 / 입금 / 출금 / 확인 필요**로 거래를 살펴보고 **JSON 저장**을 누릅니다. 저장 파일에는 모든 정상 거래와 오류 행 정보가 포함됩니다.

먼저 소수 거래가 있는 짧은 기간으로 확인하세요. 팝업은 다른 곳을 클릭하면 닫히므로 미리보기 뒤 바로 저장하면 됩니다.

KB 빠른조회에서 표를 직접 골라야 할 때는 **계좌거래내역정보목록**을 선택하세요. 0.2.2부터 `내통장표시내용`과 `의뢰인/수취인`이 위아래에 표시되는 두 줄을 거래 한 건으로 읽습니다. 통장 표시가 비어 있어도 의뢰인/수취인은 별도로 표시됩니다.

## KB 빠른조회 자동 갱신 (0.5.4)

1. 이미 작업 폴더의 확장을 사용 중이면 Chrome의 확장 프로그램 관리 화면에서 **코매칭 입금 장부 → 새로고침**을 누르고 버전 0.5.4을 확인합니다. ZIP으로 옮겼다면 새 압축을 풀고 그 안의 `extension` 폴더를 로드합니다.
2. KB 빠른조회에서 오늘을 포함하는 기간, **전체** 또는 **입금내용만**, **최근 거래내역이 위로**를 선택해 조회합니다. 확장 팝업에서 **거래내역 읽기 → 자동 조회 시작**을 누릅니다.
3. 팝업을 닫고 은행 탭은 열어 두세요. **3분 자동 조회 시작**을 누르면 첫 조회는 약 3분 뒤이며 이후에도 3분마다 예약합니다. 앞선 조회가 진행 중이면 그 회차는 건너뜁니다. 같은 탭에서 팝업을 열면 완료 횟수, 마지막 갱신 시각과 해당 페이지 내역을 볼 수 있습니다. **자동 조회 중지**로 끝냅니다.

결과표 갱신을 15초 내 확인하지 못하거나 인증이 필요하면 멈춥니다. 은행 화면을 확인하고 다시 시작하세요. Chrome 종료·PC 절전 중에는 새 내역을 읽을 수 없습니다. 날짜가 바뀌면 기간을 다시 지정합니다. 전송을 연결하면 확인된 페이지를 따라가며 이전 거래 시각까지 읽습니다. KB 거래표 바로 아래에 조회조건이 있는 화면에서는, 하단에 **다음**이 보이면 다음 거래를 읽고 빈 하단이면 마지막 페이지로 처리합니다. 여러 페이지는 첫 조회부터 다시 대조합니다. 페이지 경계가 모호하거나 도중에 행이 바뀌면 팝업에 보류 사유가 표시됩니다. KB 원본과 조회 기간을 다시 확인하세요.

## 서버로 보내기

서버 담당자가 README의 **서버 준비**를 마친 뒤 사용하세요. KB 결과 탭의 장부 팝업에서 **서버로 입금 전송 → 수신 서버 선택 → 수집 전용 토큰 입력 → 전송 연결**을 누릅니다. 현재 열려 있는 페이지는 **현재 입금 보내기**로 보냅니다. **자동 조회 시작**을 누르면 이후 갱신된 페이지는 자동 전송됩니다.

팝업에서 대기 묶음 수와 최근 서버 접수 시각을 확인할 수 있습니다. **전송 중지** 후에도 기존 대기 내역은 보존됩니다. 브라우저를 다시 시작하면 동일 서버에 토큰을 다시 입력해 전송을 재개하세요. 관리자 **결제 승인 관리 → KB 계좌 입금 대조**에서 마지막 정상 조회 시각을 확인하세요. 자동 승인의 초기 상태는 꺼짐입니다. 켜면 이후 입금과 유효 대기 주문을 대조합니다. 동명이인 건은 원본을 확인한 뒤 입금과 주문을 하나씩 골라 **연결 승인**을 누릅니다.

## 첫 행사 전 리허설

1. 한 PC에서 수취 계좌를 열고 자동 승인을 꺼 둡니다. KB 원본과 관리자 장부의 건수·금액, **마지막 정상 조회**가 두 회차 이상 갱신되는지 확인합니다. 페이지가 여러 장이면 첫 페이지와 다음 페이지의 경계에 있는 거래도 확인합니다.
2. 승인 테스트에 사용할 대기 주문을 만든 뒤 **자동 승인 켜기**를 누릅니다. 다음 초에 송금한 고유 이름·금액의 한 건이 승인되고 아이템이 한 번 지급되는지 확인합니다.
3. 같은 이름·금액으로 겹친 두 주문은 미연결 목록에 남는지 확인합니다. 한 건을 수동 승인한 뒤에도 다른 건이 계속 대기해야 합니다.
4. 스위치를 끄고 들어온 입금이 다시 켠 후에도 수동으로 남는지 확인합니다. 네트워크 복구 후 팝업의 대기 묶음이 줄고, 7분 이상 정상 조회가 끊겼을 때 설정한 운영 알림이 도착하는지 확인합니다.

## 확인할 것

- 첫 입금 한 건의 금액과 통장 표시가 **KB 원본과 장부에서 일치하는가?** 저장한 JSON의 `account.bank`는 선택한 은행인 `kb`여야 합니다.
- JSON의 날짜·시각, 입금액, 거래내용, 건수가 은행 표와 맞는가?
- 동일한 1,000원 입금이 여러 건이면 모두 남는가?
- 거래고유번호가 표시되는가? `순번`이나 화면 행 번호는 거래고유번호가 아니다.
- 표를 못 찾거나 오류 행이 생기는가? 카드형 화면, 다른 도메인의 프레임, 병합 셀은 지원되지 않을 수 있다.

KB는 [10분 동안 서비스 이용이 없으면 자동 로그아웃](https://obank.kbstar.com/quics?page=C019414)된다고 안내합니다. 장부의 **새로 읽기**는 표시 중인 표만 읽습니다. 세션 만료 후에는 은행에 다시 로그인해 같은 날짜를 조회한 뒤 장부를 다시 여세요. 자동 조회가 멈췄다면 은행 화면을 확인한 뒤 다시 시작하세요. 빠른조회에는 [사전 계좌 등록](https://obank.kbstar.com/quics?articleId=829&bbsMode=view&boardId=689&page=C019795)이 필요합니다.

은행 연결/조회 가능 여부와 오류 문구, 표의 **열 제목만** 알려주면 다음 수정을 좁힐 수 있습니다. 비밀번호·인증정보는 보내지 마세요. 거래 파일을 공유할 때는 이름·잔액·계좌 관련 내용을 가립니다.

## 현재 상태

- 합성 테스트에서 KB 빠른조회 병합 행, 같은 1,000원 거래 12,000행의 파싱, 회차 간 페이지 대조를 검증합니다.
- 브라우저에서 합성 표 추출 → 미리보기 → JSON 다운로드 확인.
- 설치된 0.2.2 확장으로 실제 KB 빠른조회 화면에서 두 줄짜리 입금 한 건의 건수와 합계가 원본과 맞는지 확인했습니다.
- 이 ZIP의 확장 프로그램은 현재 페이지를 수동 추출하거나 KB 빠른조회 결과를 로컬과 운영 모두 3분 간격으로 갱신합니다. 백엔드 소스의 독립 실행 도구로 합성 입금의 30초 주기 수집과 서버 수신도 검증할 수 있습니다. 실행 방법은 저장소 README의 ‘합성 입금 30초 수집’을 참고하세요.

자세한 데이터 형식과 테스트 실행은 [README.md](README.md)를 참고하세요. 실제 금융내역이 포함된 파일은 ZIP/소스 폴더에 넣어 재배포하지 마세요.
